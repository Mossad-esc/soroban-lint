# SOR003 · missing-ttl-extension

**Rule ID:** `SOR003`  
**Name:** `missing-ttl-extension`  
**Default severity:** warning  
**Category:** Storage / TTL  
**Status:** Implemented  

---

## What it detects

A write to `persistent()` or `instance()` storage in a public entrypoint
without a matching `extend_ttl` call on the **same storage tier** in the same
function body.

| Write call | Required extension |
|---|---|
| `env.storage().persistent().set(…)` | `env.storage().persistent().extend_ttl(…)` |
| `env.storage().instance().set(…)` | `env.storage().instance().extend_ttl(…)` |

`temporary()` writes are intentionally out of scope.

---

## Why it matters

Soroban state entries have a time-to-live (TTL).  Persistent entries that are
not extended eventually become archived and require restoration — effectively
making them unavailable until a restore is performed.  Contracts that forget
TTL management can break in production long after tests pass, losing user
balances, configuration, or ownership records.

---

## Vulnerable

```rust
// The user registration will expire when the TTL runs out.
pub fn register(env: Env, user: Address) {
    user.require_auth();
    env.storage().persistent().set(&DataKey::User(user), &true);
    // ↑ MISSING: no extend_ttl call
}
```

---

## Safe

```rust
pub fn register(env: Env, user: Address) {
    user.require_auth();
    let key = DataKey::User(user);
    env.storage().persistent().set(&key, &true);
    env.storage()
        .persistent()
        .extend_ttl(&key, TTL_THRESHOLD, TTL_EXTEND_TO);
}
```

For instance storage:

```rust
pub fn set_admin(env: Env, admin: Address) {
    admin.require_auth();
    env.storage().instance().set(&DataKey::Admin, &admin);
    env.storage().instance().extend_ttl(TTL_THRESHOLD, TTL_EXTEND_TO);
}
```

## Known limitations

- **Helpers are not credited yet.**  If an entrypoint calls a private helper
  that performs the `extend_ttl`, the rule will emit a false positive.  This
  will be resolved in the call-graph pass (Phase 2).  Until then, suppress
  the finding inline:

  ```rust
  // soroban-lint: allow(SOR003) reason="extend_ttl is called in bump_instance_ttl helper"
  pub fn store(env: Env, key: DataKey, val: u32) {
      env.storage().persistent().set(&key, &val);
      Self::bump_instance_ttl(&env);  // helper contains extend_ttl
  }
  ```

- **Instance vs persistent tier mismatch.**  An instance `extend_ttl` does
  not satisfy a persistent write, and vice versa.  The rule checks each tier
  independently.
