# SOR008 · std-or-float-usage

**Default severity:** error  
**Category:** Compatibility

## What it detects

Code in contract crates that is incompatible with Soroban's WebAssembly execution environment:

1. Missing `#![no_std]` at the crate root.
2. `use std::…` imports outside test code.
3. `std::` qualified paths in non-test code.
4. `f32` or `f64` types anywhere in non-test code.
5. Float literals (e.g., `1.0`, `3.14f64`) in non-test code.

## Why it matters

Soroban contracts compile to WebAssembly in a constrained environment where the Rust standard library is not available. Using `std` will cause build failures when targeting wasm32. Floating-point arithmetic is also problematic: it is non-deterministic across platforms and not supported in Soroban's execution model.

## Vulnerable example

```rust
// soroban-lint: vulnerable
// Missing #![no_std]
use std::collections::HashMap;

pub fn ratio(a: i128, b: i128) -> f64 {
    a as f64 / b as f64
}
```

## Safe example

```rust
// soroban-lint: safe
#![no_std]

// Use fixed-point integer math instead of floats.
const SCALE: i128 = 1_000_000;

pub fn ratio(a: i128, b: i128) -> i128 {
    (a * SCALE) / b
}
```

The `#![cfg_attr(not(test), no_std)]` form is also accepted:

```rust
// soroban-lint: safe
#![cfg_attr(not(test), no_std)]
```

## Configuration options

None.

## How to suppress

```rust
// soroban-lint: allow(SOR008) reason="f64 used only for off-chain display, not stored or transmitted"
```

## Known false positives and blind spots

- The rule is only active on files identified as contract crates (containing a `#[contract]` struct or `#[contractimpl]` block). Pure helper library crates are not analyzed.
- `use std::…` inside `#[cfg(test)]` is not flagged, but the rule does not deeply track all conditional compilation attributes; only top-level `#[cfg(test)]` on modules and functions is respected.
