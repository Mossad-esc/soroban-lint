# SOR001 · missing-require-auth

| Property | Value |
|---|---|
| **ID** | SOR001 |
| **Name** | `missing-require-auth` |
| **Default severity** | `error` |
| **Category** | Access control |
| **Status** | Implemented |

---

## What it detects

A public entrypoint inside a `#[contractimpl]` block that:

1. Writes to contract storage — any method-call chain that contains `storage()`
   and ends in a mutating call (`set`, `remove`, `bump`, `extend_ttl`), and
2. Never calls `require_auth()` or `require_auth_for_args()` anywhere in the
   function body (including inside nested blocks, `if` expressions, closures,
   and `match` arms).

---

## Why it matters

In Soroban, authorization is **explicit**. The runtime does not implicitly
restrict who may call a contract function. If an entrypoint that changes
balances, ownership, or configuration does not require authorization from the
right `Address`, anyone can call it and alter state they do not own.

This is one of the most common and most serious smart-contract vulnerabilities
across all chains, and it is entirely preventable.

---

## Vulnerable example

```rust
#[contractimpl]
impl Token {
    pub fn transfer(env: Env, from: Address, to: Address, amount: i128) {
        // No authorization: anyone can move `from`'s funds.
        let from_bal = Self::balance(&env, &from);
        let to_bal = Self::balance(&env, &to);
        env.storage().persistent().set(&DataKey::Balance(from), &(from_bal - amount));
        env.storage().persistent().set(&DataKey::Balance(to), &(to_bal + amount));
    }
}
```

**Diagnostic output**

```text
error[SOR001]: entrypoint `transfer` writes to storage but never calls `require_auth`
  --> contracts/token/src/lib.rs:42:12
   |
42 |     pub fn transfer(env: Env, from: Address, to: Address, amount: i128) {
   |            ^^^^^^^^
   |
   = help: call `from.require_auth()` before mutating state
   = docs: https://github.com/Mossad-esc/soroban-lint/blob/main/docs/rules/SOR001.md
```

## Safe examples

### Using `require_auth`

```rust
pub fn transfer(env: Env, from: Address, to: Address, amount: i128) {
    from.require_auth();
    // ... balance updates
}
```

### Using `require_auth_for_args`

```rust
pub fn approve(env: Env, from: Address, spender: Address, amount: i128) {
    from.require_auth_for_args(
        (symbol_short!("approve"), spender.clone(), amount).into_val(&env),
    );
    // ... write allowance
}
```

### Read-only entrypoint — no finding

```rust
pub fn balance(env: Env, who: Address) -> i128 {
    env.storage()
        .persistent()
        .get(&DataKey::Balance(who))
        .unwrap_or(0)
}
```

## Configuration

```toml
[rules.SOR001]
enabled = true
severity = "error"   # override to "warning" if needed

# Functions that are intentionally permissionless and should not trigger SOR001
[rules.SOR001.allow_functions]
names = ["bump_ttl", "get_price"]
```

The `allow_functions` option is planned and not yet implemented.

---

## Suppressing a finding

Use an inline suppression comment when a function is intentionally
permissionless (for example, a public `deposit` credited to the
caller-supplied address):

```rust
// soroban-lint: allow(SOR001) reason="permissionless by design; credits caller-specified address"
pub fn deposit(env: Env, to: Address, amount: i128) {
    // ...
}
```

Always include a `reason`. Reviewers should be able to tell why the check was
skipped.

---

## Known false positives

- **Auth delegated to a private helper.** If both the `require_auth` call and
  the storage write live inside a private helper function that is called by the
  entrypoint, the rule will produce a false positive until the Day 4 call-graph
  pass is implemented.  Suppress such cases inline with a `reason` comment.

- **Intentionally permissionless functions.** A public `deposit` that credits
  the *caller-specified* address, or a `bump_ttl` helper, may legitimately omit
  auth.  Suppress these explicitly.

---

## Storage API methods treated as mutations

| Method | Description |
|---|---|
| `set` | Write a value |
| `remove` | Delete an entry |
| `bump` | Deprecated TTL bump |
| `extend_ttl` | Extend the entry's time-to-live |
