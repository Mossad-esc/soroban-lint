# SOR004 · critical-data-in-temporary

**Default severity:** error  
**Category:** Storage

## What it detects

Writes to `temporary()` storage where the key expression's name suggests critical state. A key matches when any of the configured `critical_keys` patterns (default: `admin`, `owner`, `balance`, `allowance`, `config`, `supply`) is a case-insensitive substring of the key's identifier or enum variant name.

## Why it matters

Temporary storage in Soroban has a time-to-live (TTL) that, if not extended, causes the entry to expire and be silently deleted. Losing an admin address, a user balance, or an allowance because they lived in temporary storage is a critical correctness and security failure.

## Vulnerable example

```rust
// soroban-lint: vulnerable
env.storage().temporary().set(&DataKey::Admin, &admin);
```

## Safe example

```rust
// soroban-lint: safe
env.storage().instance().set(&DataKey::Admin, &admin);
env.storage().instance().extend_ttl(1000u32, 10000u32);
```

## Configuration options

```toml
[rules.SOR004]
enabled = true
severity = "error"
# Key names treated as critical (case-insensitive substring match)
# This list REPLACES the default list when set.
critical_keys = ["admin", "owner", "balance", "allowance", "config", "supply"]
```

## How to suppress

```rust
// soroban-lint: allow(SOR004) reason="nonce is intentionally temporary and non-critical"
env.storage().temporary().set(&DataKey::Nonce(user), &true);
```

## Known false positives and blind spots

- The rule uses naming heuristics. If your project uses non-standard key names for critical data, those are not detected.
- The rule only analyzes the direct key argument to `set()`; it resolves one level of local variable assignment but cannot trace through complex expressions.
- Cross-function key resolution (a key returned from a helper) is not tracked.
