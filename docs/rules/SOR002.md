# SOR002 · unchecked-arithmetic

**Rule ID:** `SOR002`  
**Name:** `unchecked-arithmetic`  
**Default severity:** warning  
**Category:** Arithmetic  
**Status:** Implemented  

---

## What it detects

1. **AST analysis** – raw `+`, `-`, `*`, `/`, `%` and compound-assignment
   variants (`+=`, `-=`, `*=`, `/=`, `%=`) applied to integer-typed values
   inside public entrypoints.

2. **Manifest inspection** – a `Cargo.toml` at the workspace root whose
   `[profile.release]` section does not set `overflow-checks = true`.

---

## Why it matters

In Rust, release builds wrap on integer overflow by default.  For financial
logic in a Soroban contract, silent wrap-around is a serious correctness and
security bug.  A balance that wraps from 0 to `i128::MAX` is exploitable.

Contracts should either:
- Use `checked_add`, `checked_sub`, etc. and return a typed error on overflow,
  **or**
- Set `overflow-checks = true` in `[profile.release]`, which converts overflows
  into panics (which abort the transaction) rather than silent wraps.

---

## Vulnerable

```rust
// Silently wraps in release builds without overflow-checks.
let new_balance = balance + amount;
```

```toml
# Cargo.toml — no overflow-checks means silent wraps in release.
[profile.release]
opt-level = "z"
```

---

## Safe

```rust
let new_balance = balance
    .checked_add(amount)
    .ok_or(Error::Overflow)?;
```

```toml
# Cargo.toml — panics on overflow in release builds.
[profile.release]
overflow-checks = true
```

---

## Configuration

```toml
[rules.SOR002]
enabled = true
severity = "warning"
# Also inspect the workspace Cargo.toml for overflow-checks.
check_cargo_profile = true   # default: true
```

## Heuristics and false positives

Because the rule operates on the pre-expansion syntax tree without a type
resolver, it uses heuristics:

- Operands with integer literal suffixes (`1i128`, `0u64`, …).
- Explicit type annotations on `let` bindings or function parameters
  (`i128`, `u128`, `i64`, `u64`, `i32`, `u32`, etc.).
- Named variables that were bound from any of the above.

**The rule deliberately prefers false negatives over noisy false positives.**
It does *not* flag:

- Arithmetic where all operands appear to be non-integer.
- Arithmetic inside `const`/`static` expressions.
- Arithmetic on literals only (e.g. `1 + 1`).

If you receive a false positive, suppress it inline with a reason:

```rust
// soroban-lint: allow(SOR002) reason="custom Add impl never overflows by invariant"
let new_val = val + delta;
```

---

## Checked alternatives

| Raw operator | Safe alternative |
|---|---|
| `a + b` | `a.checked_add(b).ok_or(Error::Overflow)?` |
| `a - b` | `a.checked_sub(b).ok_or(Error::Underflow)?` |
| `a * b` | `a.checked_mul(b).ok_or(Error::Overflow)?` |
| `a / b` | `a.checked_div(b).ok_or(Error::DivisionByZero)?` |
| `a % b` | `a.checked_rem(b).ok_or(Error::DivisionByZero)?` |
